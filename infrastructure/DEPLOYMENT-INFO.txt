STEP 1: ADD PERMISSIONS TO IAM USER
================================================================================
Your IAM user 'nastto-admin' needs AdministratorAccess to deploy infrastructure.

Option A - AWS Console (Easiest):
  1. Login to AWS Console with ROOT account
  2. Go to: IAM → Users → nastto-admin
  3. Click "Add permissions" → "Attach policies directly"
  4. Search for "AdministratorAccess"
  5. Select it and click "Add permissions"

Option B - AWS CLI with Root:
  aws iam attach-user-policy \
    --user-name nastto-admin \
    --policy-arn arn:aws:iam::aws:policy/AdministratorAccess

================================================================================
AFTER DEPLOYMENT
================================================================================

1. Get all resource details:
   aws cloudformation describe-stacks \
     --stack-name nashtto-infrastructure \
     --query 'Stacks[0].Outputs' \
     --output table

2. Update GoDaddy Nameservers:
   - Get nameservers from stack outputs
   - Login to GoDaddy
   - Update DNS to use Route 53 nameservers
   - Wait 24-48 hours for propagation

3. SSH into EC2:
   ssh -i infrastructure/cloudformation/nastto-key.pem ec2-user@<EC2_PUBLIC_IP>

4. Verify Java installation:
   java -version
   # Should show: Java 21 (Amazon Corretto)

5. Check environment variables:
   cat /opt/nashtto/.env

6. Deploy your Spring Boot JAR:
   scp -i nastto-key.pem your-app.jar ec2-user@<IP>:/opt/nashtto/
   ssh ec2-user@<IP>
   java -jar /opt/nashtto/your-app.jar

================================================================================
TROUBLESHOOTING
================================================================================

If deployment fails:

1. Check IAM permissions:
   - User must have AdministratorAccess

2. Check SSH key pair:
   - Must exist in us-east-1: nastto-key

3. Check CloudFormation events:
   aws cloudformation describe-stack-events \
     --stack-name nashtto-infrastructure \
     --query 'StackEvents[?ResourceStatus==`CREATE_FAILED`]'

4. Common errors:
   - Key pair not found → Create it first
   - Invalid CIDR → Check IP format (x.x.x.x/32)
   - Weak password → Min 8 alphanumeric chars
   - Permission denied → Add AdministratorAccess to IAM user
